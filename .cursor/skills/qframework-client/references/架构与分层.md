# 架构与分层

## 入口

- 全局架构类：`GameApp extends Architecture<GameApp>`（`assets/script/game/GameApp.ts`）。
- 访问方式：`GameApp.Interface`（继承 `Architecture.InitArchitecture()`，幂等；无需自定义 `bootstrap()`）。

## 分层与目录

| 层 | 目录 | 基类/约定 | 职责 |
|----|------|-----------|------|
| 入口 | `game/GameApp.ts` | `Architecture<GameApp>` | 注册模块、初始化 ResKit/UIKit |
| Controller | `game/controller/` | `AbstractController` | 场景/节点、按钮、输入；调 Command/Query/System |
| System | `game/system/` | `AbstractSystem` | 长生命周期：网络、音频 `AudioSystem`、UI 门面 `UISystem`、Bundle、频道总线 |
| Model | `game/model/` | `AbstractModel` | 可持久/可绑定业务状态，不直接操作 Node；活动子包优先 `BindableProperty<T>` 暴露可观察字段 |
| Command | `game/command/` | `AbstractCommand` | 写操作、流程编排 |
| Query | `game/query/` | `AbstractQuery` | 只读查询 |
| Event | `game/event/` | `class XxxEvent` | 架构类型事件（无基类要求，须为 class） |
| Utility | `game/utility/` | `IUtility` | 无架构状态的工具、适配器 |

subpackage 业务脚本放在对应 bundle 的 `script/` 下；若需架构能力，同样继承上述基类并通过 `GameApp.Interface` 访问。

## 允许依赖（自上而下）

```
Controller → Command, Query, System, Model, Utility, UIKit
System     → Model, Utility, 其他 System（谨慎）, Toolkits
Command    → System, Model, Utility, SendEvent
Query      → System, Model, Utility
Model      → Utility, SendEvent
```

**禁止**：

- Model / Utility 依赖 Controller 或 `cc.Component`。
- System 直接操作具体 Panel 节点（应发事件或由 Controller 打开 UI）。
- 在任意层 new 第二个「全局 Architecture」（仅 `GameApp`）。

## 与 Cocos 生命周期

- `AbstractController` 是 `cc.Component`：用 `onLoad` / `start` / `onDestroy` 处理节点生命周期。
- 在 `onLoad` 中 `RegisterEvent` 时，链式 `UnRegisterWhenGameObjectDestroyed(this.node)`。
- 架构 `System.Init` 在 `GameApp.InitArchitecture` 完成注册后调用一次，**不要**在 Controller `onLoad` 里 `RegisterSystem`。

## subpackage 与主包

- 主包 `assets/script/game`：全局 System、登录/大厅入口 Controller。
- subpackage：玩法/大厅 UI Panel 与局部 Controller；共享 System 仍从 `GameApp.Interface.GetSystem` 获取。

## Bundle 集中管理（精简版）

- **配置**：`game/config/BundleManifest.ts` — `BundleKey`（全部 bundle）、`SubGameId`（仅子游戏）、`bundleName` 字符串（与 Cocos 目录名一致）、场景与 Dialog 列表。
- **能力**：`game/system/BundleSystem.ts` — `enterGame(SubGameId)`、`goLobby()`（`BundleKey.Lobby`）、`openDialogAsync(..., BundleKey, prefab)`。
- **状态**：`game/model/GameplayContextModel.ts` — `subGameId`；`leaveGame` 时 `reset()`。
- **映射**：`resolveBundleKey(subGameId)`、`tryGetSubGameId(bundleKey)`；大厅/活动只用 `BundleKey`，不走 `enterGame`。
- **流程**：`EnterSubGameCommand` / `LeaveSubGameCommand`（`game/command/EnterSubGameCommand.ts`、`LeaveSubGameCommand.ts`）或 Controller 直接 `GetSystem(BundleSystem)`。
- **子包 script（第一阶段）**：仅有 **scene 根** `*SceneController.ts`（继承 `game/controller/engine/BaseController.ts`）；activity / 无场景 function bundle **可不建 TS**，元数据在 Manifest。
- **基类目录**：`game/controller/engine/` — `BaseController`（场景 Controller）、`BaseDialog`（`extends UIPanel`）。
- **后续**：某玩法变复杂时，该 bundle 内最多再加 **一个** `{Game}Logic.ts`；Dialog 类放在 `script/ui/*Dialog.ts` 并继承 `BaseDialog`，就绪后 `BundleSystem.registerPanel`。

## 活动子包：Model 数据与 Dialog 绑定

- **Model**：`readonly page = new BindableProperty<PageDto | null>(null)`（记录页可加 `records`）；禁止 `cc.Component`。
- **Command**：`this.GetModel(FooModel).page.value = dto`；不为同一 DTO 再 `SendEvent(PageUpdated)`。
- **Dialog**：`RegisterWithInitValue` + `UnRegisterWhenGameObjectDestroyed(this.node)`；`@property` 只绑节点/资源。
- **类型事件**：失败 toast、`ClaimSuccess` 动效、Rummy 打开局内窗等**副作用**仍用 `SendEvent`。
